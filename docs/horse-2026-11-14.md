## UI correction found during live validation

The first deployed image used the cloud handoff revision. Public health, TLS,
asset hashes and production authentication restrictions passed, but a full
browser game exposed another instance of the refresh race: a click on Play
could be silently dropped while the one-second background refresh held the
shared operation guard.

Commit `f3fe9a9` separates background refreshes from user operations and prevents
late responses from replacing newer room state. The regression holds a room
refresh response open, selects and plays a card before releasing it, and checks
that the stale response does not restore the played card. It failed against the
previous binary and passes with the fix. The lost-response simulation now drops
only successful responses, preserving genuine version-conflict retries.

The full browser suites were rerun successfully against the final committed
fix. The corrected image was rebuilt natively and applied with the existing PVC.
A consistent online SQLite backup before the update passed `PRAGMA
integrity_check` and is stored at
`/var/backups/pastimer/pastimer-20261114-pre-refresh-fix.sqlite` on Horse.

## Apply and operate

Import the tested image archive into Horse's existing k3s containerd before
applying the manifest. Ensure the bot Secret exists. Generate the manifest from
the repository root:

```sh
kubectl kustomize deploy/horse > /tmp/pastimer-horse.yaml
ssh -o ClearAllForwardings=yes horse 'sudo -n kubectl apply -f -' < /tmp/pastimer-horse.yaml
ssh -o ClearAllForwardings=yes horse 'sudo -n kubectl -n pastimer rollout status deployment/pastimer --timeout=180s'
ssh -o ClearAllForwardings=yes horse 'sudo -n kubectl -n pastimer get deployment,pod,pvc,service,ingress,certificate'
curl --fail https://1000.vartanyan.com/api/health
```

For later releases, build and import a new immutable image reference, update the
overlay, take a consistent SQLite backup, and apply with the same PVC and one
writer. Preserve the previous image for rollback. Never delete the namespace or
PVC as a deployment shortcut. The local-path volume is on Horse; this deployment
does not establish scheduled or off-host backups.

The bot's default menu button can be set through
[Telegram's setChatMenuButton API](https://core.telegram.org/bots/api#setchatmenubutton)
to open the HTTPS root. A Main Mini App/profile launch button is a separate
optional BotFather setting; see
[Telegram's launch modes](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button).
